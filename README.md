# Обработка отзывов в Triton

MiniLM превращает отзыв в эмбеддинг.

Классификатор определяет тональность отзыва.

Qwen пишет ответ на негативный отзыв. На позитивный возвращается «Спасибо за ваш отзыв!» без вызова генерации.

Цепочкой управляет Python BLS-модель `review_pipeline` внутри Triton.

## Модели

| Этап | Модель | Бэкенд |
|---|---|---|
| Эмбеддинги | paraphrase-multilingual-MiniLM-L12-v2, 384 признака | Python |
| Классификация | LogisticRegression, экспорт через skl2onnx | ONNX Runtime |
| Генерация | Qwen2.5-0.5B-Instruct | Python-адаптер к отдельному vLLM |
| Управление цепочкой | review_pipeline | Python BLS |

Запускала на Mac M1 Pro через Docker Desktop, Linux ARM64, CPU. NVIDIA GPU не используется. Qwen работает в FP32, без квантования; лимит ответа — 128 токенов.

Классификатор обучается на эмбеддингах отзывов из [data/reviews.csv](data/reviews.csv). Небольшой учебный набор: 32 обучающих примера и 8 отложенных. `0` — негативный отзыв, `1` — позитивный.

## Запуск

```bash
uv sync
docker volume create otus-triton-hf-cache
docker compose build triton
```

Подготовить MiniLM и ONNX-классификатор:

```bash
docker compose run --rm prepare
```

Запустить серверы:

```bash
docker compose up triton
```

Порты Triton: `8000` — HTTP, `8001` — gRPC, `8002` — метрики. vLLM доступен с Mac на порту `8003`; внутри Compose адаптер обращается к `http://vllm:8000/v1`.

Дождаться `READY` у четырёх моделей. Во втором терминале отправить один запрос к BLS:

```bash
uv run python scripts/client.py
```

Или передать свой отзыв:

```bash
uv run python scripts/client.py "Отличный товар покупкой довольна"
```

## Результат

Вся цепочка с генерацией отвечает в среднем за **5,90 секунды** при одном одновременном запросе. Около **98,8% серверного времени** занимает генерация.

## Что сделано

Развёрнут пайплайн обработки отзывов: MiniLM → классификатор → генерация ответа на негативный отзыв. BLS принимает один запрос, вызывает модели и возвращает класс, вероятности и ответ.

Triton выполняет ONNX-классификатор и Python-модели. Qwen работает в отдельном контейнере vLLM; Python-модель `generation` вызывает его по HTTP.

Конфигурации и код:

| Модель | Конфигурация | Код |
|---|---|---|
| embeddings | [config.pbtxt](model_repository/embeddings/config.pbtxt) | [model.py](model_repository/embeddings/1/model.py) |
| classifier | [config.pbtxt](model_repository/classifier/config.pbtxt) | [prepare_models.py](scripts/prepare_models.py) |
| generation | [config.pbtxt](model_repository/generation/config.pbtxt) | [model.py](model_repository/generation/1/model.py) |
| review_pipeline | [config.pbtxt](model_repository/review_pipeline/config.pbtxt) | [BLS model.py](model_repository/review_pipeline/1/model.py) |

Имена зависимых моделей заданы параметрами BLS-конфига; порядок вызовов определяет Python-код. Во всех моделях `max_batch_size: 0`, один экземпляр `KIND_CPU`.

## Проверка запуска

Запрос через [client.py](scripts/client.py), отзыв «Товар сломался в первый день»:

```text
Класс: негативный
Вероятности [негативный, позитивный]: [0.9262446  0.07375541]
Ответ: Ваш отзыв о товаре был очень неожиданным и неприятным. Мы с удовольствием предоставим вам бесплатную замену или поддержку, если это возможно. Пожалуйста, уточните, что именно вы хотите сделать, чтобы мы могли помочь вам лучше.
Завершение генерации: stop
```

Цепочка работает, но ответ модели нельзя считать готовым ответом магазина: она предлагает бесплатную замену, хотя правила возврата ей не передавались.

## Нагрузочное тестирование

Mac M1 Pro, Docker Desktop, Linux ARM64, CPU. Triton 24.01 (2.42.0), Perf Analyzer из SDK 24.01, vLLM 0.33.0. GPU не используется.

Каждая модель и BLS измерялись отдельно: HTTP, один одновременный запрос, batch size 1, окно измерения 30 секунд. Генерация: FP32, temperature=0, max_tokens=128.

Эмбеддер и BLS получали один и тот же негативный отзыв. Генератор получал тот же промпт, который строит BLS.

### Скорость работы

| Модель | RPS | Средняя задержка клиента, мс | p95, мс | Запросов |
|---|---:|---:|---:|---:|
| embeddings | 11,2399 | 88,989 | 150,127 | 1214 |
| classifier | 4954,4 | 0,201 | 0,240 | 535847 |
| generation | 0,166651 | 5765,549 | 6409,558 | 18 |

Первый тест эмбеддера с окном 10 секунд не достиг стабильности за 10 окон. После увеличения окна до 30 секунд замер завершился успешно.

Полный текст сохранённых фрагментов: [логи Perf Analyzer](docs/PERF_ANALYZER_LOGS.md).

### На что уходит время

Серверные этапы отдельных моделей, миллисекунды:

| Модель | Queue | Compute Input | Compute Infer | Compute Output |
|---|---:|---:|---:|---:|
| embeddings | 0,042 | 0,018 | 88,480 | 0,068 |
| classifier | 0,030 | 0,003 | 0,007 | 0,003 |
| generation | 0,039 | 0,017 | 5765,053 | 0,060 |

BLS выполняется около 5,9 секунды. Это время включает вызовы всех вложенных моделей; большую его часть занимает генерация.

Внутри одного BLS-замера серверные задержки составили:

| Этап | Средняя задержка, мс |
|---|---:|
| embeddings | 71,451 |
| classifier | 0,118 |
| generation | 5827,366 |
| Весь BLS-запрос | 5900,162 |

**Основное узкое место — генерация: около 98,8% серверного времени цепочки.** Классификация занимает очень мало времени. Очереди при одном одновременном запросе малы.

## Что можно улучшить

1. Проверить совместимое с CPU квантование или более лёгкую модель
2. Проверить несколько одновременных запросов. Для vLLM сейчас установлен `max-num-seqs=1`
3. Попробовать Dynamic Batching для эмбеддера
